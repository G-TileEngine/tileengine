## E8. Budget fields (project.json)
- Home: **`settings.budgets?`** in `project.json` (§3.1 settings table), not top level. It is a project-wide knob like the other settings rows. Names accepted as proposed: `units`, `activeAi`, `effects`, `stageTiles`.
- Shape: `budgets?: {units?, activeAi?, effects?, stageTiles?: {warn: int ≥ 1, limit: int ≥ warn}}`. Project-wide, applied to each stage separately. No per-stage override in 11c (a later `stage.budgets?` would be additive).
- Every key is optional. **An absent key means that budget is not checked** (no row). Templates and the demo write all four; the numbers are data, pending the CEO's strictness answer through the CoS, and are not format.
- An entry that breaks the shape (non-int, warn < 1, limit < warn, not an object) gives the warning **`budgetInvalid`** (where `project.json#/project/settings/budgets/<key>`, detail = the stored value as JSON; a `budgets` value that is not an object gives one `budgetInvalid` at `project.json#/project/settings/budgets` and nothing is checked) and that budget is not checked. No repair, no rounding.
- Unknown keys under `budgets` are kept on save (r13 R4) and ignored, no row.
- Read only by the project reader's report (Test gate, Build game, the step-36 export). **The runtime, sim and core never read it.** It ships in the export like any `settings` field (E5(b) verbatim bytes) and is part of `project.json`, so it is in the project hash like every other stored field.
- `tile-project` stays v6: optional field, no migration.
- core-types (additive; **CN-029**, byte-exact diff staged at data/staging/cn-budgets/cn-budgets.diff against core-types 439f403d; 11c1 declares the types locally until CN-029 lands):
  `export type BudgetKey = "units" | "activeAi" | "effects" | "stageTiles";`
  `export type BudgetLimit = { readonly warn: number; readonly limit: number };`
  `export type ProjectBudgets = Partial<Readonly<Record<BudgetKey, BudgetLimit>>>;`
  and `budgets?: ProjectBudgets` on the project settings type.

## E9. Budgets exception to C4 and §10
- C4 (§3.1 settings row) becomes: "No caps; ranges warn only (C4), **except `settings.budgets` (§10.1)**."
- §10 gains §10.1: "Budgets are the one exception to 'Nothing ever blocks on size or count'. Byte meters stay warn-only."
- Rows, one per stage per checked budget, from `readProject().report`:
  - **`budgetNear`**, warning, when warn ≤ used ≤ limit.
  - **`budgetOver`**, severity `hard`, when used > limit. Over replaces near; a stage never gets both for one budget.
  - `where` = `stages/<stageId>.json#` (the stage doc, root pointer), also for stageTiles (a map shared by two stages gives a row per stage).
  - `detail` = JSON `{budget, used, limit}` in that order; stageTiles adds `w, h` (map cols, rows) after `limit`.
- `budgetOver` is a gate row, **not an H code**: the project still opens, edits and saves; only Test and Build game (and the step-36 export) block, through the one `testGate`. The editor never stops anyone adding (UX ruling).

## E10. Counting rules (start state of the stage, no play needed)
Bodies are counted from the stored stage, with the stage's effective sides: loadout bodies on `sides.loadout ?? "player"`, enemy pool on `sides.enemyPool ?? "rival"`, neutrals on `neutrals[].side ?? sides.neutrals ?? "neutral"`. Objects (TILE-layer occupants) never count. Bodies spawned during play (summons, reinforcements) are not counted; the runtime FX/sim limits cover them.
- **units** = start tiles that hold a body + every enemy pool placement + every `neutrals[]` entry. Player start tiles count as `min(effective loadout.size, start tiles)`, the most bodies the loadout can place.
- **activeAi** = counted bodies whose side is neither the loadout side nor `neutral` (matches R17 `sidesOf`). Reassigning `sides.enemyPool` to the loadout side drops them from activeAi, not from units.
- **effects** = **distinct effect ids** reachable from the stage's counted bodies: every non-`none`, non-null `effect` answer in those units' setups and in `neutrals[].setupIds`, after E4 resolution (prefixed alias read as the bare id; an effect doc id and a bare BTF id are different ids). Unresolved ids are not counted (they already give a row). Effects in `rules` are ignored (E2) and not counted. Reason: the UX fix line is "Remove some effects", and the 8/12 numbers only make sense per distinct effect; a per-unit count would put most BTF stages over.
- **stageTiles** = `cols × rows` of the stage's `mapRef` map as stored.
- **Absent `settings.budgets`** (old projects): **no budget rows, no engine default, no migration, and the maker does not write budgets on save in 11c** (no new write-side work; E7, D9 still EA backlog). New projects get budgets from the template data. A partial object checks only its keys. Writing budgets into old projects waits for the budget editing step.

## E11. Phone-like Test flag
- Home: §11.3 editor prefs (`tileengine/editor-prefs.json`). Not a bare list: **`projects?: Record<projectId, {phoneTest?: boolean}>`**, so later per-project maker prefs share one key instead of new ad-hoc lists. Absent entry or absent `phoneTest` = off.
- `editor-prefs` stays v1; an unknown value reads as the default; no migration.
- **Never in the project, never exported, never synced, never in the project hash, never read by the runtime or Render.** The maker passes it to Test as a launch option.
- A duplicated or imported project has a new id, so it starts off. Entries for deleted projects are tolerated and may be pruned on the next prefs write.

## E10a. Counting where E10 was silent (EA 11c1 trial, 2026-11-26 23:0x)
- **weighted** pool places `min(picks, spawns.length)`, and with `allowRepeats: false` also at most `entries.length`.
- **waves** pool counts its **largest single wave** (max over waves of the sum of `count`) in units and activeAi, not 0. Waves are authored stage placements, unlike summons; counting 0 would let a waves stage skip both budgets.
- **effects** use the whole setup list of every unit that can appear: the effective loadout roster when the team is non-zero, every pool entry's unit when the pool places any (weighted entries, all wave entries), every neutral's unit, plus `neutrals[].setupIds`. Confirmed.
- **`stage.overrides.setups`** are not read in 11c (known limit, listed in r42).
