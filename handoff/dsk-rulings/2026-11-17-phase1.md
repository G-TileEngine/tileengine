## D1. Rules state in match saves (P1-2): no format bump, no CN
- `match-save` stays at formatVersion 1 (project-format §6.9.1). Its `snapshot` is engine-owned (typed `unknown` in core-types) and is a check value; the log is the truth.
- The rules state goes in as an optional key `snapshot.rules` (rules-owned: HP, alive, per unit instance). The §6.9 number rules apply (finite, no NaN/±Infinity/-0).
- Older saves have no `snapshot.rules`. On load, the replay rebuilds the rules state, and the snapshot check compares `rules` only when the saved snapshot has it. So the `migrations/save/` hook stays empty and old saves load as they are.
- This doesn't touch core-types, since `MatchSave.snapshot` is `unknown`.

## D2. Talk text (P1-3 interact): a setup answer, no CN
- An NPC is a `stage.neutrals[]` entry, and its role is `neutrals[].setupIds` (§6.5 r15). For Phase 1 this is **DECIDED** (it was PROPOSED).
- The talk line is the answer to a `text` knob (setup-format type "text", `max_len`) on a talk behaviour setup. That needs a catalogue entry from the Librarian, not a unit field or a stage field, and no CN.
- The host reads the resolved answer when `unit.interacted` fires. A missing or empty line shows nothing.

## D4. Text length unit (B1/B5 `label`, `max_len`)
- "chars" means **Unicode code points** (`[...s].length`), not UTF-16 code units, so 25 emoji count as 25. The editor may show grapheme counts, but the stored rule is code points. Over-length is still only an `outOfRange` warning.
- This still has to be written into setup-format §2.9 and `TextKnobExtras`, together with strayValue (§2.5).

## D5. UX r73 re-cut (ux-r73-recut.md): `unit.talk` and `unit.fx` are not stored fields (01:0x)
- These are **not** added to unit v2. Talk text is per placement, since two NPCs of the same unit type can say different things. Effects already have one home: the owner setup's `effect` answer (A1 ruling).
- **In memory they're fine.** stage-live's per-placement unit may carry `talk` and `fx: {attack?, talk?}` for Test mode and for the `world` passed to TE. Test mode never saves, so this doesn't touch the format.
- **When saved** (r73 Save, or later), they're written as setup answers on that placement:
  - talk text goes to the talk setup's `line` (text, max_len 140 code points, default "Hello, traveller."), via `neutrals[].setupIds` (D2);
  - `fx.talk` goes to the talk setup's `effect` (ref, docs:"effect"), and `fx.attack` to the basic-attack setup's `effect` on that placement.
  - The Librarian supplies the catalogue knobs. Empty or "None" means a default answer, so no key is written.
- **Upgrades (r73 2c):** deferring them is OK only while nothing writes files. If r73's Save writes stage or project files, §12 steps 004/005 and map 004 run at load in the same round, so a file is never written in mixed versions.
