## Goal
Make every place the engine takes a value from a caller (a "front door") refuse a strange or booby-trapped value by name instead of crashing, and make the world always do exactly what the log recorded. At the base: a hand-built action with a bad `target`, `durationMs` or `effects` throws out of `submit`; an action edited after `submit` is logged as one thing and applied as another (the log/world desync); an `unlock` with sparse `effects` (`[ , "guard"]`) is logged and the engine's own log no longer reads back (QA step-19 residual 1); a getter can answer one value to the check and another to the log (residual 2); `moveTo` keeps the caller's cell object; `createLevels`, `createWorld`, `replay` and `restore` throw raw `TypeError`s on getters, proxies and revoked proxies; a forged huge snapshot tick replays for minutes before it is refused; `clock.after` misuse throws; the gesture mapper turns a NaN position into a cell; chaos-gen reads its mix live. After this step: (1) **one door copy**, `plainCopy`, reads a value once into fresh, deep-frozen plain data or answers `NOT_PLAIN`, never throwing; (2) each door copies, then checks, then uses only the copy, and a refusal has a name; (3) hostile tests reach every door.

Rulings in this step (Engine Architect, 2026-11-12):
- **Copy, then check, then use only the copy (SE-01's `copy()` contract, made general).** A door reads the caller's value exactly once. Checking the caller's object and then using it (or reading it again) is the hole. The log, the world and a timed `apply` all get the **same frozen copy**, so the world does what the log says even if the caller edits its object later.
- **One helper, in an existing layer.** `src/core/plain.ts` holds the copy; `readAction` in `src/core/log` is the one action door (copy + the log's own shape check). No second copy function anywhere in `src`; no `JSON.parse(JSON.stringify(…))` as a door copy (it turns `Infinity` into `null`, which a reader may then accept, and it runs `toJSON`).
- **A refused action is never logged and never throws.** `submit` gives `unlockFailed` when the copy says `kind: "unlock"` and is not a valid action (as in step 19), else the new notice `actionRefused`. A value that cannot be copied at all (a throwing getter, a proxy, a hole anywhere, a cycle) is `actionRefused`: its `kind` is never read twice. So QA residual 1 (sparse `effects`) is `actionRefused`, not `unlockFailed` (CEO question 1 below).
- **A timed action lands as logged.** Step 19 re-read a timed unlock's `effects` when it landed (an edit after `submit` gave `unlockFailed`). Now the copy is what was logged and is frozen, so it lands as logged; step 19's test is changed to say so. The log stays the single source of truth.
- **Misuse of `clock.after` is refused, not thrown.** A non-integer or negative `ms`, or a `cb` that is not a function, is reported to `onError` as a `RangeError` and returns an inert timer `{ id: 0, dueMs: -1, cancel() {} }` that never fires. Valid timer ids start at 1, so `id 0` means "refused".
- **An array's length is a shape, read once (QA HOLD, step-20 review).** A real array's `length` is an integer ≥ 0; a proxy can answer `Infinity` and claim every index as its own, so no hole is ever found and, with the default budget `Infinity`, the walk never ends (it hung `submit`). `plainCopy` refuses a length that is not an integer ≥ 0, and a length above the values left in the budget, before reading any item. This is a shape check, not a cap: the budget stays the caller's.
- **Rebased on the merged step 19 by intent (build A).** A's `idsOf` (the check-then-use read of `effects`) is replaced by the door copy as in r1; A's `createLevels` reader (`taken`) keeps its name and its throw, but reads the setup once through `plainCopy` instead of field by field; A's `apply` keeps its move branch and its `choose(…) !== true` test.
- **No new numeric caps.** Depth and node budgets are the copy's parameters; this step uses only fixed shape depths (1, 2, 3, 5) and `Infinity` for whole documents (a nest too deep for the stack is still `NOT_PLAIN`). Document caps, replay-length caps and log-length caps are H2's, with CEO-accepted numbers.
- **The project readers are reached through `createWorld` / `replay`, which copy the whole input first.** A direct call of `readStage` (etc.) on a live hostile object can still throw: guarding it inside `src/project` needs the project layer to import `src/core/plain.ts`, which is a dependency rule (a CN). Carried to H3 by name.

Behaviour (exact; each line has a test):
1. **The door copy (`plainCopy(value, depth, nodes)`).** Returns fresh, deep-frozen plain data or `NOT_PLAIN`; **never throws**, whatever the value. Strings, booleans, `null` and `undefined` are kept; numbers are kept with `-0` as `0` (`NaN` and `Infinity` are kept: the door's own check refuses them). Functions and symbols are dropped (an object key holding one is left out, as JSON does). Keys `__proto__`, `constructor` and `prototype` are left out (no prototype pollution: the copy's prototype is `Object.prototype`). `toJSON` is never called. Only own enumerable string keys are read (`Object.keys`), each **once**. An array's `length` is read once and must be an integer ≥ 0 and no more than the values left in the budget (else `NOT_PLAIN`, before any item is read); then it is read by index `0…length-1`; an index that is not an own property (a hole) is `NOT_PLAIN`. `NOT_PLAIN` also for: a throwing getter, proxy trap or revoked proxy; a bigint; an object whose prototype is not `Object.prototype` or `null` and is not a plain array (a class instance, `Map`, `Date`); a nest deeper than `depth` containers (the top value is depth 0); a nest too deep for the stack (a cycle included); more than `nodes` values in total. `cellOf(v)` is `plainCopy(v, 1)` with integer `c` and `r`, frozen, else `null`.
2. **The action door (`readAction`, `append`, `parseLog`).** `readAction(v)` = `plainCopy(v, 3)` (action, target, cell) and the log's existing action check, which now also needs **integer** cell `c` / `r` and `turns` finite or `null`; it returns the copy or `null`. `append(tick, action)` checks the tick as at the base, then throws `RangeError("append: not an action")` for `null`, and stores only the copy (an edit of the caller's action after `append` changes no entry). `parseLog` of a non-string is `{ ok: false, error: "not JSON" }`; each entry's action goes through `readAction` (else `bad entry`, as at the base). The engine's own log always reads back: `parseLog(log.toJSON())` gives the same text.
3. **`submit` and `apply`.** After the `disposed` return: `copy = plainCopy(action, 3)`, `own = readAction(copy)` (or `null` when `copy` is `NOT_PLAIN`). If `own` is `null`: push `unlockFailed` when `copy` is a record with `kind === "unlock"`, else `actionRefused`; return — **not logged, no throw, nothing else changes, no clock error**. Else `log.append(tick, own)`, then `apply(world, own)` now or `clock.after(own.durationMs, () => apply(world, own))`. `apply` reads only that frozen copy (step 19's `idsOf` re-read is gone: `effects.length === 1 ? effects[0]`, `""` still refused). So a bad `target` (no `at`, a NaN, Infinity or 1.5 cell), a bad `durationMs` (-1, 1.5, NaN, Infinity, a string), `turns: NaN`, a missing `effects`, sparse `effects`, a throwing getter, a proxy, a revoked proxy, a cycle, a bigint, a `Map`, a 100k-deep nest or a `via.ref` nested deeper than three levels is refused by name. An action edited after `submit` lands as logged, and `replay` of the log gives the same snapshot (no desync).
4. **`moveTo` keeps its own cell.** `moveTo(id, cell, cause)` reads `cell` once with `cellOf`; `null` gives `{ ok: false, reason: "outOfBounds" }` (after the `unknownUnit` / `notAlive` checks, as at the base). The unit stores the frozen copy; a later edit of the caller's object moves nothing.
5. **`clock.after` says no politely.** A non-integer or negative `ms` (including NaN, Infinity, a string, `null`) or a non-function `cb`: `report(new RangeError("after: ms must be an integer >= 0 and cb a function"))` (the `onError` path) and return `{ id: 0, dueMs: -1, cancel() {} }`; nothing is scheduled and the clock's state is unchanged. A valid `after` is unchanged (ids from 1). The disposed clock behaves as at step 17.
6. **`createLevels`** reads `setup` once with `plainCopy(setup, 3)` (setup → rules / pools → arrays) and checks and uses only that copy; the pools are the frozen copy; `levels.rules` is a frozen `{ bar, thresholds, offerLevels, offerSize, xp: { move } }` built from it. A hole, a throwing getter, a proxy, a revoked proxy, a cycle, a deep nest, a bigint or a `Map` in the setup, the rules, `thresholds` or a pool throws the step-18 `RangeError("createLevels: bad rules or pools")`. A getter that flips after its first read is read once. Step 19 Behaviour 2 is otherwise unchanged.
7. **`createWorld`, `replay`, `restore`.** `createWorld(input)` uses `plainCopy(input, Infinity)` (no depth cap until H2) and only the copy reaches the readers, the core and `createLevels`; not a record → `Error("createWorld: input is not plain data")`. `replay` copies `input` the same way first (`Error("replay: input is not plain data")`). `restore(input, log, snap)` copies `snap` with `plainCopy(snap, 5)`; not a record or `phases` not a record → `Error("restore: snapshot is not plain data")`. **Before any replay work** it requires: `tick` an integer ≥ 0, `clockMs === tick × stepMs`, and `logSeq` equal to the number of log entries with `tick ≤` the snapshot tick; otherwise `Error("restore: snapshot does not match the log")` at once (a forged tick `1e9` is refused in milliseconds, not replayed). Then it replays to that tick, sets phases from the copy, and compares `snapshot(world)` with the copy as at the base. A good snapshot restores as at the base.
8. **The gesture mapper** reads each sample once with `plainCopy(sample, 1)`; a sample that is not a record, or whose `x` or `y` is not finite (NaN, ±Infinity), gives `[]` and changes no gesture state. Every other sample is handled as at the base (the `ms` RangeError included).
9. **chaos-gen reads its settings once.** `chaosIntents(gen, legal)` copies `gen` with `plainCopy(gen, 2)` when the hook is made; the hook checks and draws only from the copy; if the copy is `NOT_PLAIN`, the hook's first call throws `RangeError("chaos-gen: gen must be plain data")`. An edit of the caller's `gen.mix` after the hook is made changes no draw. A run record still holds the caller's `gen` (as step 19 did for the hunter).
