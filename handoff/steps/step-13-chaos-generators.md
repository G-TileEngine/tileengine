## Goal
Give the chaos player its hands and its scissors. `chaosIntents(gen, legal)` is a seeded `IntentHook` for `runChaos`: on every hook call it draws one input **kind** from the caller's weights (`mix`) on its **own** stream `streamSeed(world.seed, gen.stream)` and answers with that kind's batch of 09c intents: the caller's sensible moves (`legal`, in tests the test AI `forward` as intents), a stall, or one of seven illegal or odd batches (off-grid taps, enemy or unknown unit ids, taps on taken or closed cells, cancel spam, confirm with nothing to confirm, box-select, and pointer samples fed through `createGestureMapper`). `runChaosGen` runs it through step 12 and writes the generator settings into the record. `shrinkChaos(input, record, tools)` is the simple shrink (CEO Q4): ddmin over the record's move list, keeping a shorter list only when it still breaks the **same invariant with the same `firstDivergentSnapshotKey`**, and returns a smaller record that `replayChaos` reproduces. A report-only smoke on both official boards runs in `npm run green` and shrinks anything it finds.

This is step C of `docs/chaos-player-outline.md` §7 (A = `step-11-player-driver`, merged at `1ff51d9`; B = `step-12-chaos-harness`, merged at `9dad92a`). It is the last of the three chaos steps.

Rulings in this step (CEO 2026-11-10 and 2026-11-11, via Chief Of Staff; Engine Architect 2026-11-11):
- **Where it lives: `src/sim/chaos-gen.ts` and `src/sim/shrink.ts` (product code, no Change Notice).** The dev-side exploit hunter (outline §9) reuses the generator and the shrink. `src/sim/chaos.ts` stays at its merged 124 lines and is not edited.
- **Online play is just another driver (CEO standing rule).** The generator and the shrink only return intents to `runChaos` / `replayChaos`. They never call `submit`, `feedIntent`, `createPlayer`, `runMatch`, `moveTo` or the log, and never write phases. Nothing in `src/core`, `src/state`, `src/rules`, `src/runtime`, `player.ts`, `driver-phase.ts` or `chaos.ts` is edited.
- **Seeded only, one clock (law 1; outline §3):** the generator's `Rng` is `createRng(streamSeed(world.seed, gen.stream))`, separate from the match stream (`"match"`), the placement stream (`"pool"`) and the test AI stream (`"ai"`, tests). It never reads `world.rng`, so the step-12 end-of-run `(a)4` replay (which compares `rngState`) stays the guard. Gesture sample times are `world.clock.now()` plus whole ms offsets; the generator never steps the clock. No `Date`, `performance.now`, timers or `Math.random`.
- **Weights are the caller's, no defaults (law 12):** `mix`, `burst`, `stream` and the `GestureOptions` are required inputs; `src/` has no numeric default and no preset. The swarm-style variation per run (research: mostly sensible moves, a share of bad ones, a different mix per seed) is the caller's: the smoke builds one mix per seed in the test. The test stream name is `"chaos"`; the gesture thresholds are the 09c test values `{ cellPx: 64, tapMaxPx: 10, holdMs: 500 }` (no BTF gesture preset exists; CEO question below).
- **Recorded, so replay is exact (outline §4):** `runChaosGen` adds `chaosGen: gen` to the run's `presets`, so the record's `options.presets.chaosGen` holds the stream name, the mix, the burst and the gesture thresholds. Replay itself never calls the generator: `replayChaos` feeds the recorded intents (step 12 Behaviour 8).
- **Gestures reach the door only through the touch mapper (CEO Q2).** A gesture batch is the output of a fresh `createGestureMapper` fed one of five recipes that are the (a)10 edge cases (tap at exactly `tapMaxPx` and `holdMs − 1`; drag; hold of exactly `holdMs` that also moves far; first-pointer ownership with an `up` before any `down`, a second `down` from the owner and a second pointer; owner `cancel`). The record keeps the mapper's intents, not the samples (Not in this step).
- **The shrink replays a subset by side and order, not by call number (exact rule in Behaviour 7).** A record is keyed by hook call (step 12 Behaviour 3); dropping a move changes which calls stall, so a candidate keyed by the old call numbers would desync (`chaos: replay diverged`). Instead every candidate is a fresh `runChaos` whose hook serves the kept moves in order, one original call's group per hook call, only to the side that fed it; any other ask stalls. The candidate's own record (new call numbers) becomes the new current list, so the result is always a record `runChaos` made and `replayChaos` reproduces.
- **No retry (outline §5):** the shrink runs each candidate once; it first replays the input record and finally replays its result with `replayChaos`, and throws if either differs. Same record in, same record out.
- **Report-only (CEO Q6/Q7; gate in outline §6):** the smoke never asserts that a run is clean. A found failure is shrunk, printed with `t.diagnostic`, and must replay. A record that does not replay is a determinism bug against (a)4/(a)5 and fails the test, as in step 12.
- **BTF defaults only (CEO Q9), the two official boards and the reach-far-row end rule (CEO Q5); rejects are a pass, but listed (CEO Q3).** The illegal kinds produce rejects the step-12 result lists; with `CHAOS_CHECKS` on the merged engine they are never a failure.

Behaviour (exact; each line has a test). `rng` is the generator's stream; `cell()` is `{ c: rng.int(cols), r: rng.int(rows) }` (column drawn first) on `world.grid`; draws happen in the order written.
1. **Settings, checked when `chaosIntents` is called (no defaults):** `RangeError` (message starts `chaos-gen: `) when `stream` is `""`, `"match"` or `"pool"`; when the keys of `mix` are not exactly the nine `CHAOS_KINDS`; when a weight is not finite or is < 0, or all are 0; when `burst` is not an integer ≥ 1; when `mix.gesture > 0` and `gestures` is `null`. When `gestures` is not `null` it is checked by calling `createGestureMapper(gestures, { cols: 1, rows: 1, unitAt: () => undefined })` once, so its `RangeError`s surface here.
2. **One stream per run:** on the first hook call the generator binds that call's `world` and creates `rng = createRng(streamSeed(world.seed, stream))`; a later call with another `world` throws `Error("chaos-gen: one generator per run")`. It never reads `world.rng`.
3. **One kind per hook call:** `kind = CHAOS_KINDS[rng.weighted(<the mix weights in CHAOS_KINDS order>)]`. `legal` returns `legal(world, side, budget)` unchanged (no further draw); `stall` returns `[]`; any other kind returns `[]` when `budget.units` is empty, else draws `id = rng.pick(budget.units)` and returns the kind's batch (Behaviour 4).
4. **The batches** (`sel(x)` = `{ intent: { type: "SelectUnit", unitId: x } }`, `tap(sq)` = `{ intent: { type: "TargetCell", at: sq } }`, `n = 1 + rng.int(burst)`):
   - `offGrid`: `a = cell()`, then `rng.pick` of `[{ c: −1, r: a.r }, { c: cols, r: a.r }, { c: a.c, r: −1 }, { c: a.c, r: rows }]` → `[sel(id), tap(that)]` (reject `offGrid`).
   - `foreign`: `rng.pick` of the ids of living units of every other side (in `units.all()` order) followed by the unknown id `` `${id}#` ``, then `cell()` → `[sel(that id), tap(cell)]` (rejects `notOwn` or `noUnit`, then `noEvent`).
   - `taken`: `rng.pick` of the in-bounds cells, row by row (`r` outer, `c` inner), that are closed or have at least one occupant (the selected unit's own cell included) → `[sel(id), tap(that)]` (submitted, then `moveFailed` in the core: the unit stays, `logSeq` + 1).
   - `cancel`: `n`, then `[sel(id), n × { intent: { type: "Cancel" } }]` (the first `Cancel` is accepted, the rest are `illegal`).
   - `confirm`: `n`, then for each of the `n` confirms `a = cell()` and `rng.pick([null, a])` as its aim → `[sel(id), n × { intent: { type: "Confirm" }, aim }]` (every one `noEvent`: nothing is targeting).
   - `box`: `[{ intent: { type: "BoxSelect", from: cell(), to: cell() } }]` (`noEvent`).
   - `gesture`: `from = rng.pick([<id's cell>, cell()])`, `to = cell()`, then `rng.pick(gestureRecipes(from, to, world.clock.now(), gestures))`; the samples are fed in order to a fresh `createGestureMapper(gestures, { cols, rows, unitAt: (at) => world.units.occupantAt(at) })` and the batch is every intent it returns, in order, as `{ intent }`.
5. **`gestureRecipes(from, to, ms, g)`** returns five sample lists, with `p(kind, id, at, t, dx = 0)` = `{ kind, id, pointer: "touch", x: at.c × g.cellPx + dx, y: at.r × g.cellPx, ms: t }`: (tap) `down 0 from ms`, `up 0 from ms+holdMs−1 dx=tapMaxPx`; (drag) `down 0 from ms`, `move 0 to ms`, `up 0 to ms`; (hold) `down 0 from ms`, `up 0 to ms+holdMs`; (ownership) `up 1 to ms`, `down 0 from ms`, `down 0 to ms`, `down 1 to ms`, `up 1 to ms`, `up 0 from ms`; (cancel) `down 0 from ms`, `cancel 0 from ms`, `up 0 from ms`.
6. **`runChaosGen(input, opts)`** is `runChaos(input, { ...<opts without gen and legal>, presets: { ...opts.presets, chaosGen: opts.gen }, intents: chaosIntents(opts.gen, opts.legal) })`.
7. **`shrinkChaos(input, record, tools)`, ddmin over `moves`, no retry:**
   - First `replayChaos(input, record, tools)`; unless its `failure` is `JSON.stringify`-equal to `record`, throw `Error("chaos: record does not replay")` (so every step-12 replay check applies too).
   - A **candidate** is a sub-list `kept` of the current record's moves (order kept). It is tried once (`tries` + 1) with `runChaos({ ...input, hostSeed: record.seed }, { ...tools, ruleset, sides, fuse, maxRounds, maxSimMs, moveMs, idPrefix, presets <all from the record>, intents: serve(kept) })`. `serve` keeps a cursor: when the side asking is the side of the next kept move, it returns that move and every following kept move with the same `call`, as `{ intent, aim }`, and moves the cursor past them; otherwise (another side, or nothing left) it returns `[]`. The candidate is **kept** only if the run has a failure whose `invariant` and `firstDivergentSnapshotKey` equal the input record's; that failure record becomes the current record.
   - **Order:** chunk size starts at `ceil(n / 2)` (`n` = moves in the current record). A pass drops `[start, start + size)` for `start = 0, size, 2·size, …`, skipping an empty `kept`, and stops at the first kept candidate. After a kept candidate the size becomes `min(size, ceil(n / 2))` for the new `n` and the next pass starts at 0; after a pass with none kept, a size of 1 ends the shrink, else the size becomes `ceil(size / 2)`.
   - Finally `replayChaos(input, <result>, tools)`; unless its `failure` equals the result, throw `Error("chaos: shrunk record does not replay")`. Return `{ record: <result>, tries }`. The same input record always gives the same `{ record, tries }`; a record that cannot shrink comes back unchanged.
