## The short version (7 takeaways)

1. **AI's problem is consistency, not single pictures.** Every tool that works locks the style *before* it generates: SpriteCook draws the whole screen as one concept and cuts pieces from it, then reuses that concept as the style reference; it also has Themes and Presets. PixelLab and Retro Diffusion take reference images; Scenario and Retro Diffusion "My Styles" train on your own art. One-at-a-time generation drifts (outline weight, light, corner radius).
2. **"Real pixel art" is a clean-up step, not a model.** The good tools force the result onto a true pixel grid and a fixed palette afterwards: Retro Diffusion's Pixel Art Fixer finds the grid and snaps to it; SpriteCook's colour mode *Force* remaps every pixel to the nearest palette colour; PixelLab has "Force colors". **We already own this step offline:** the Imagine converter's Crisp look (Combo A: 2-pass OKLab downscale, k-means palette, near-black outline, ≤16 colours). That is our edge: let any AI make the picture, our converter makes it pixel-true.
3. **Animate by moving pixels, not by redrawing frames.** PixelLab's skeleton tool, SpriteCook's tree clumps (1 px loops) and Raymond Schlitter's hand technique all keep identity by moving parts. AI-drawn in-between frames drift off-model. Our `body-map.js` already does this for walks (regions move 1 px; frames 1/3 contact, 2/4 passing). That is the shortest route to the CEO's bar: a 32×32 hero, 4 directions × 4 frames, in under 10 minutes on a tablet.
4. **UI pieces are sliced, not generated at size.** Draw or generate one small piece, mark its 9-slice borders, and stretch it to any size with crisp corners. SpriteCook's border editor (four sliders, *Suggest*, a live stretch preview, "apply to the whole state family") is the pattern to borrow. Text is never baked in: the engine draws the real strings.
5. **Buttons come in state families.** Normal / pressed / disabled / selected (plus hover, on/off, checked, empty/fill) are named and grouped together. Makers should draw one and get the rest derived from the palette ramp.
6. **One palette is the spine for sprites *and* UI.** SpriteCook, PixelLab and Retro Diffusion all lock a colour count and palette per project (Retro Diffusion can import Lospec palettes). If the UI kit is built from the project's own ramp, the menus match the sprites with zero extra taps.
7. **Start from good references, not from a blank prompt.** CC0 kits (Kenney's pixel UI pack, 500 files) and reference libraries (Game UI Database, filterable by screen type) beat prompting from nothing for layout and state coverage.
