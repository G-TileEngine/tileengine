## Law 12 — every new `catch` / `try` / `??` / `||` default in the diff

**Judged product items (as asked)**

- `src/editor/rules/levels.ts:13`: `list(row["knobs"]).filter(isObj).find((item) => item["id"] === id) ?? null`. A missing knob becomes `null`; `curveOf` / writers then return `null` or `{ mode: "missing" }`. Not a hidden value.
- `src/editor/rules/levels.ts:28` and `:54`: `const raw = full[i] ?? defaults[i]; if (typeof raw !== "number") return null` / `{ mode: "missing" }`. This is the guide L157 fill: raising `n` takes new rows from the slice default list at that index. If both the stored list and the slice default lack a number, the write is refused. Not a silent numeric default.
- `tools/maker/project.ts:9`: `${input.tail ?? ""}${input.units ?? ""}${input.levels ?? ""}`. Optional slot, same pattern as the existing `tail` / `units` holes; `home.ts:39` always passes `levels: levelsSection(...)`.
- `tools/maker/home.ts:155`: `go(\`l:set:${node.getAttribute("data-lvl") ?? ""}:${node.value}\`)` inside a `hasAttribute("data-lvl")` branch. An empty attribute would send an empty key; every live slider sets `data-lvl` to `levels`, `xp_move`, or `row-<i>` (`tools/maker/levels.ts:19, 31`).
- `tools/play-stage/match.ts:133–134` (the strip). The code is not a single `thresholds[level] ?? 0`; it is:

```
const at = levels === null ? undefined : levels.rules.thresholds[bar?.level ?? 0];
const xp = levels === null ? null : { level: bar?.level ?? 0, now: bar?.xp ?? 0, need: typeof at === "number" ? at : 0, top: bar !== undefined && bar.level >= levels.rules.thresholds.length || typeof at !== "number" };
```

  HUD (`hud.ts:34`) then renders `row.top ? \`Level ${row.level} · Top level\` : \`Level ${row.level} · ${row.now}/${row.need} XP\``.

  **When is `thresholds[level]` undefined?** The engine types say the top level is `thresholds.length` (`src/rules/levels/types.ts:4`). `pay()` stops when `bar.level >= top` (`levels.ts:56–66`). So the one legitimate in-match state where `thresholds[bar.level]` is missing is **the player's bar at the top level (`bar.level === thresholds.length`)**. In that state `typeof at !== "number"` is true, `top` is true (`&&` binds before `||`), and the strip shows **"Level n · Top level"**. The `need: 0` fallback is not shown. It does not mislead the user as a "0 XP to the next level" line.

  **The other reachable undefined-bar case** is at **Test start, before any XP is paid.** `createLevels` keeps `bars` empty until `gain()` / `ensure()` (`levels.ts:37, 69–70, 87`). `view()` then has `bar === undefined`, so `bar?.level ?? 0` indexes `thresholds[0]`, `top` is false, and the strip shows "Level 0 · 0/\<thresholds[0]\> XP". That is the real initial bar (level 0, 0 XP, next cost = first threshold), which the smoke pins ("Level 0 · 0/2 XP") and `a move pays XP in Test` asserts as `{ level: 0, now: 0, need: 2, top: false }`. It is not a silent mid-game default.

  A hole in the middle of a valid `install` table is not reachable: `XP_LEVELS.install` slices a numeric list (`xp-levels.ts:9–15`) and `rules === null` throws (`project.ts:42–43`). If `at` were ever not a number with `bar.level < length`, `top` would still be true (the `typeof at !== "number"` arm), so the strip would say "Top level" rather than "0/0".
